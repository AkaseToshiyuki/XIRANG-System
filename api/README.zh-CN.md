# API 契约

[English](README.md) | [简体中文](README.zh-CN.md)

- `openapi/xirang-v1.yaml` 描述网页控制台和 `xirangctl` 使用的管理 API。
- `proto/xirang/v1/agent.proto` 描述由 Agent 主动发起的 mTLS 控制流。

服务端提供管理、接入、节点生命周期和 mTLS 心跳端点。Agent 在本机生成私钥和
CSR，控制平面 CA 签发具有节点 URI SAN 的证书。管理接口还提供两阶段证书轮换、
管理员吊销和按时间倒序的生命周期审计。生成的 Go 绑定提交在 `gen/xirang/v1`；
`make generate` 重新生成绑定，`make contract-check` 验证源契约。

任务状态消息分别限制 stdout 和 stderr 尾部为 64 KiB。运行期间，协商后的日志
快照最多每秒更新两次，认证后的作业 SSE 端点暴露最新完整快照，不保存无界分块
历史。节点 SSE 事件同样携带节点的完整最新状态，客户端按节点 ID 覆盖旧值。

可选能力均通过能力协商启用，包括原生执行、证书轮换、管理面板中继、硬件清单、
资源遥测、网络拓扑、流量归因、原生构建和多节点任务。Agent 在确认任务前持久化
分配，并在重连后重放最新结果。控制器负责提交、资源预留、重试和诊断查询。

管理面板命令只携带启用状态。Agent 从接入状态取得固定上游地址，持久化状态并在
心跳中报告；没有管理角色的 Agent 不监听面板端口。

拓扑报告在生成版本前会校验前缀、地址、MAC、字段长度、数量和时间。探测链路只有
存在精确反向地址观测时才具有正容量；有效容量取双向声明的较小值，延迟取双向
中位数的较大值。控制器选择一条最优健康链路，其余物理链路作为有序备用，容量
不做叠加。

## 兼容性规则

1. 不复用已有字段号。
2. `v1` 内只增加可选字段；破坏性修改使用 `v2`。
3. 每条命令和报告具有不可变消息或分配 ID。
4. 所有可选行为都经过能力协商。
