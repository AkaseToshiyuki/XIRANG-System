# XIRANG 1.4.1 版本说明

[English](RELEASE_NOTES.md) | [简体中文](RELEASE_NOTES.zh-CN.md)

XIRANG 1.4.1 将新建 API token 改为一次性认证，修复账户登录与令牌登录的身份
显示和默认选项，增加告警忽略与节点状态重新判断。版本同时包含 1.3.0 之后开发的
主备控制器、自适应网络路径及共享存储改进。管理 API 与 Agent 协议保持 `v1`。

## 登录与一次性令牌

- 新建 API token 首次认证成功后立即失效，消费记录与审计在同一事务提交，
  并发请求最多一个成功。认证成功后，即使请求的操作因权限不足被拒绝，令牌也已消费。
- 账户会话显示 `local_password`；创建 token 不替换当前会话，退出后默认回到账户
  登录。API token 列表不再混入交互会话，并区分未用、已使用、过期和撤销状态。
- 控制台通过 `POST /api/v1/auth/token` 将未用 token 兑换为独立会话，原 token
  不可再次使用。会话最多十二小时且不超过原到期时间，权限不超过兑换时上限；
  账户升级不扩大其权限，账户禁用后拒绝访问，会话不能通过兑换接口自行续期。
- 密钥仍只在创建时显示。密码登录会话、配置的引导管理员凭据与 OIDC 凭据保持
  原有认证生命周期，它们不属于用户创建的一次性 API token。

## 告警与节点状态

告警中心增加需确认的“忽略”操作及“已忽略”视图，操作者、时间和事件状态跨
重启保留。忽略不会将问题标为已修复，也不删除观测；过期版本的操作会被拒绝。

已忽略事件不再影响节点警告/异常灯色。节点依据其余告警、连接、维护状态和实时
硬件传感器重新判断，其他故障仍存在时可以继续亮红灯。状态转换通过事件流更新，
旧轮询结果不能覆盖较新的处理决定。严重性升级会重新触发，问题恢复后再发生会
创建新告警。“确认”操作也改为记录实际操作者，不再使用固定管理员名称。

## 共享存储与网络路径

- 不支持 POSIX ACL 的 NAS 共享可以使用预先配置的 Unix 用户/组权限；不会自动
  放宽已有目录权限，也不会通过写 ACL 探测 NFS 支持情况。NFS 再导出增加稳定
  文件系统标识和挂载点检查。
- `-default-shared-space=false` 允许明确替换默认共享，并避免重启后重新创建。
  artifact/build 路径和保存的任务模板需随共享迁移；取消共享配置保留原数据。
- 共享项目配额与 Agent 协商，只在已配置且支持的文件系统上强制执行。共享挂载
  未确认时阻止新工作；离线节点保留待清理状态，已删除节点退出共享状态列表。
- 节点间传输使用经过验证的路径发现与选择，按可用容量和延迟择优，定期重新
  评估并保留端点身份校验。修复相互地址切换稳定性和跨节点挂载截止时间处理；
  协商链路速率不等于实测吞吐量。

## 控制器启动与可用性

预置共享 PostgreSQL 命名空间后，可配置一个主控和一个备用，支持主控优先、
接管和稳定后交还。失去状态锁的控制器停止提供旧状态。共享身份、稳定入口和
迁移条件见[运行手册](OPERATIONS.zh-CN.md)。

缓存服务证书同时检查生效与到期时间，校时后可以保留 CA 并重签服务证书。
服务安装等待已配置的时间同步目标，并在适用时启用 timesyncd 等待服务。
构建工具链固定为 Go 1.26.11。

## 升级与验证

升级前备份状态、PKI 和配置并保留旧安装。以前已使用的非交互 API token 在
1.4.1 中视为已消费，未使用的 token 只允许一次认证。原来反复使用 API token
的集成应改用有期限的会话或受管理的 OIDC 凭据，并在到期前更新；认证监控抓取
同样适用，参见[运行手册](OPERATIONS.zh-CN.md)。主备控制器应全部升级后再使用
新认证及忽略功能；旧控制器允许重用 API token，降级前须撤销生成的凭据，不应
混用新旧鉴权实现。

后端测试覆盖一次性消费持久化与并发、会话权限上限、账户角色变化、忽略事件
生命周期和 API 权限；浏览器回归覆盖默认登录、令牌兑换、确认与节点灯色重算，
并保留其他故障的影响。这些检查不代表硬件修复、物理故障切换性能或科学正确性。

部分 NAS/NFS 不支持文件 API 使用的原子“不覆盖目标”重命名，操作会失败并保留
源文件。NFS 共享不提供 XIRANG 的 ext4/XFS 项目配额。这些限制继续明确显示；
版本不会启用后端不支持的操作，也不据此声称完成整机重启或负载验证。
